## 1. 为什么需要这份数据

文档解析、切片、检索、引用溯源、效果评测这五件事**都依赖稳定可控的测试语料**：
如果只用随手下载的 PDF，会出现"答案对不上、来源说不清、指标无法复现"的问题。
因此本数据包按以下四条原则设计：

1. **多格式覆盖**：PDF / Word / Excel / TXT / Markdown 各至少 1 份，且包含多页 PDF 与多工作表 Excel；
2. **事实可校验**：关键事实（年假天数、住宿标准、SLA 时限、密码策略等）在全部文档中**表述一致、不矛盾**；
3. **含干扰项**：`08_考勤与假期管理规定` 与员工手册主题相近但结论不同；`09_供应商对账明细` 为纯数值表，
   用于检验检索区分度与"张冠李戴"式错误引用；
4. **含无答案场景**：数据包中**刻意不包含**食堂、班车、停车场、年会、营收等信息，用于测试拒答能力（对应指标 M-04）。

## 5. 使用方法

### 5.1 直接使用（推荐，零依赖）

数据包已随仓库提交，**使用者无需安装任何依赖**：

1. 启动后端与前端服务；
2. 在知识库管理页按顺序上传 `tests/sample_docs/` 下 10 份文档（文件名已按 D-01~D-10 编号排序，便于依次上传）；
3. 等待解析完成，确认文档列表中 10 份文档切片数均大于 0；
4. 打开问答页，用第 4 节的问题进行联调与评测。

### 5.2 重新生成（可选，仅在需要修改内容时使用）

```bash
pip install python-docx openpyxl reportlab
python tests/sample_docs/generate_sample_docs.py
```

生成脚本特性：
- 使用 Windows 系统字体（微软雅黑）嵌入 PDF，保证中文可正常提取、不依赖阅读器字体；
- 输出内容完全确定（无随机、无网络请求），多次运行结果一致；
- 修改脚本中的文本常量即可批量更新全部文档，便于后续扩充数据（如新增"财务制度"）。

> 若在无微软雅黑字体的环境（如 Linux 服务器）重新生成，脚本会自动回退到黑体；两者都缺失时会明确报错，不会输出乱码文件。

### 5.3 数据版本约定

修改数据包内容时，须同步更新：本文档第 2、3 节 → `docs/需求文档_v1.md` 第 7.2 节 → PE 的评测集来源字段，三处保持一致。

## 6. 已知限制与后续计划

| 限制 | 影响 | 计划 |
| :--- | :--- | :--- |
| 不含扫描件（图片型 PDF） | 无法验证 OCR 相关能力 | v1 明确不支持 OCR（需求文档 1.5 节），无需覆盖 |
| 不含超大文件（>20MB） | 未覆盖边界性能 | 由 DEV 用临时文件单独做边界测试，不入库 |
| 供应商对账表为纯数值表 | 无法验证复杂财务口径问答 | 作为干扰项保留，第 3 周可用于检验检索精度 |
| 数据量 10 份，规模较小 | 无法验证大规模检索性能 | 需求文档 NFR-P-04 已定义容量目标，必要时由 AD 脚本批量复制扩充 |
