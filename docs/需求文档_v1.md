## 1. 项目背景与目标

### 1.1 业务背景

企业内部知识（员工手册、报销制度、IT 规范、产品资料、客户支持流程等）以 PDF、Word、Excel、TXT 等形式散落在共享盘与群文件中。员工遇到问题时：

- **找不到**：需要在十几个文件里翻找，平均耗时 10 分钟以上，且经常找错版本；
- **问不准**：同事口口相传，口径不一致；制度更新后无人知晓，新旧版本混用；
- **带不走**：知识集中在少数老员工手中，人一走知识就断档。

### 1.2 问题陈述

> 如何让"不会找文件、不愿看长文档"的普通员工，用一句大白话提问，就能在 **10 秒内**拿到一段 **基于企业正式文档、且每一句都能溯源到原文**的答案？

### 1.3 产品目标

**一句话目标**：面向企业文档的智能问答系统 —— 上传文档即可提问，答案**准确、有出处、可追溯**。

| 目标 | 说明 | 对应指标 |
| :--- | :--- | :--- |
| G1 答得准 | 答案要点与文档事实一致，不答非所问 | M-01 检索命中率、M-03 答案正确率 |
| G2 有出处 | 每段答案附引用来源（文件名 + 页码/工作表 + 原文片段） | M-02 引用准确率 |
| G3 不编造 | 文档中没有的内容明确说"未找到"，不臆造制度条款 | M-04 拒答正确率 |
| G4 用得顺 | 上传即用，无需培训；提问到出答案 ≤ 10 秒 | M-05 响应时延、M-07 易用性 |

### 1.4 成功指标（验收即以此表为准）

| 编号 | 指标 | 目标值 | 测量方法 | 责任角色 |
| :--- | :--- | :--- | :--- | :--- |
| M-01 | 检索命中率 Recall@5 | ≥ 80% | PE 用 `tests/qa_dataset_v1.json`（20 条）统计正确文档落入 Top-5 的比例 | PE |
| M-02 | 引用准确率 | ≥ 85% | 抽取 20 条答案的引用片段，人工判定"引用是否真的支撑该结论" | PE + RA |
| M-03 | 答案正确率 | ≥ 75%（20 条中 ≥ 15 条要点正确） | 对照参考答案逐条打分（完整=1 / 部分=0.5 / 错误或缺失=0） | PE + RA |
| M-04 | 拒答正确率 | ≥ 90% | 用 5 条"文档中不存在"的诱导问题测试，统计正确兜底比例 | PE |
| M-05 | 响应时延 | 检索段 P95 ≤ 1.5s；完整答案 P95 ≤ 10s | 本地 20 次调用取 P95，日志记录 `latency_ms` | DEV |
| M-06 | 文档解析成功率 | 100% | 对 `tests/sample_docs/` 全部 10 份文件解析，入库无误 | AD + DEV |
| M-07 | 首次可用时间 | 新用户 ≤ 5 分钟内完成"上传 → 提问 → 拿到带引用答案" | 找 1 名非本项目同学做可用性测试并计时 | RA |
| M-08 | 稳定性 | 连续提问 50 次不崩溃，接口错误率 < 2% | 脚本压测 + 异常场景回归 | DEV |

### 1.5 范围界定

**v1 范围内（本次必修）**

- 单租户内部知识库（不区分部门、不做数据隔离）；
- 多格式文档上传与解析：PDF / Word(docx) / Excel(xlsx) / TXT / Markdown；
- 文档切片、向量化、Chroma 向量库持久化；
- 语义检索 + Rerank 重排序（第 3 周引入并调优）；
- 带引用来源的答案生成（DeepSeek）；
- 多轮对话与历史记录；
- Streamlit 问答界面 + 知识库管理界面；
- 20 条 QA 评测集与两轮质量评估。

**v1 明确不做（防止范围蔓延，移入 v2 备选池）**

- 多租户 / 部门级权限 / SSO 单点登录；
- 扫描件 OCR、图片内文字识别；
- 网页抓取、Confluence/飞书等外部知识源同步；
- 移动端 App、微信小程序；
- 知识图谱、自动摘要推送、答案点赞排名；
- 细粒度审计日志与合规报表。

## 2. 相关方与目标用户

### 2.1 相关方

| 相关方 | 关注点 | 与需求的关系 |
| :--- | :--- | :--- |
| 企业普通员工（主用户） | 快速拿到可信答案 | 需求主要来源 |
| 新入职员工（高频用户） | 快速上手，不用打扰同事 | 典型场景 S4 |
| HR / IT / 行政（管理员） | 文档能被正确理解、答案质量可控 | 典型场景 S5 |
| 课程指导教师 / 答辩评委 | 功能完整、技术有深度、演示稳定 | 验收标准制定依据 |
| 项目组各角色 | 需求清晰、可落地、可验收 | 本文档直接服务对象 |

### 2.2 用户画像

| 画像 | 特征 | 核心诉求 | 使用频率 |
| :--- | :--- | :--- | :--- |
| U1 普通员工 | 不懂技术，用浏览器，提问口语化（"年假咋算的"） | 一句话得到答案，并相信它 | 每周 1~3 次 |
| U2 新员工 | 对制度完全陌生，问题密集且宽泛 | 快速补全认知，答案要注明出处便于细读 | 入职首月每天 |
| U3 知识库管理员 | 需要维护文档版本与质量 | 上传/删除文档、知道哪些问题答不上来 | 每周 1 次 |
| U4 演示观摩者 | 只看几分钟，关注稳定性 | 演示流畅、亮点一眼可见 | 答辩/评审当天 |

### 2.3 典型场景与用户旅程

| 编号 | 场景 | 用户动作 | 期望结果 |
| :--- | :--- | :--- | :--- |
| S1 | 制度查询 | 上传《员工手册》后提问"年假有多少天？" | 给出天数 + 引用手册页码 |
| S2 | 流程查询 | 提问"报销审批要走哪几步？" | 分步列出流程 + 引用制度原文 |
| S3 | 表格数据查询 | 提问"出差住宿标准是多少？"（答案在 Excel 中） | 从表格取值 + 引用工作表名与单元格区域 |
| S4 | 新员工速成 | 连续追问"试用期多久？""试用期有年假吗？" | 支持多轮追问，代词可指代（"那转正后呢？"） |
| S5 | 知识库维护 | 上传新版《报销制度》并要求替换旧版 | 支持删除/覆盖旧版，新答案引用新版 |
| S6 | 无答案兜底 | 提问"公司食堂几点开饭？"（文档中无） | 明确回答"未在知识库中找到依据"，并建议补充文档 |
| S7 | 演示/离线 | 答辩现场网络异常 | 演示模式可复现历史问答（缓存答案），不冷场 |

## 5. 用户故事与验收标准（Given-When-Then）

> 每张用户故事卡包含：角色故事 + 验收标准（GWT）+ 关联功能需求。GWT 是 RA 执行验收时的**逐条判据**。

### US-01 知识库管理员上传制度文档

- **作为** 知识库管理员（U3），**我希望** 上传公司的 PDF/Word/Excel 制度文件，**以便** 员工能立刻检索到最新制度。
- 前置：文件为白名单格式且 ≤ 20MB。
- **Given** 系统已启动且向量库可写，**When** 我上传《员工手册.pdf》，**Then** 系统返回成功，且知识库列表中该文件显示切片数 > 0。
- 关联：FR-DOC-01/03、FR-KB-01/02/04

### US-02 上传非法文件被拦截

- **作为** 管理员，**我希望** 上传错误文件时得到明确提示，**以便** 我知道该怎么改。
- **Given** 我选择的文件是 21MB 的 PDF 或 `.exe`，**When** 我点击上传，**Then** 系统拒绝并提示"文件超过 20MB"或"不支持的文件类型"，服务不报错、不中断。
- 关联：FR-DOC-02/04、FR-SEC-03

### US-03 员工查询制度类问题

- **作为** 普通员工（U1），**我希望** 直接问"年假有多少天"，**以便** 不用翻手册。
- **Given** 《员工手册.pdf》已入库，**When** 我提问"公司年假有多少天？"，**Then** 答案给出具体天数，且附引用（文件名 + 页码），10 秒内返回。
- 关联：FR-QA-01/02、FR-CIT-01/02

### US-04 员工核对答案来源

- **作为** 员工，**我希望** 看到答案的原文出处，**以便** 我确认制度细节。
- **Given** 答案带引用，**When** 我点击引用条目，**Then** 展开显示原文片段（非全文下载），内容与答案结论一致。
- 关联：FR-CIT-03

### US-05 员工查询流程类问题

- **作为** 新员工（U2），**我希望** 问"报销要走哪些流程"，**以便** 一次性了解步骤。
- **Given** 报销制度已入库，**When** 我提问该问题，**Then** 答案以分步骤形式给出（≥3 步），每步可溯源。
- 关联：FR-QA-01、FR-CIT-04

### US-06 查询 Excel 表格中的数值

- **作为** 员工，**我希望** 从表格中直接取数（如住宿标准），**以便** 不必自己找单元格。
- **Given** `03_报销制度与费用标准.xlsx` 已入库，**When** 我提问"出差住宿标准是多少？"，**Then** 答案给出正确数值，引用标注**工作表名**（如"差旅标准"）。
- 关联：FR-DOC-01、FR-CIT-02

### US-07 多轮追问

- **作为** 新员工，**我希望** 追问"那转正后呢？"，**以便** 像和同事聊天一样了解政策差异。
- **Given** 上一轮问了"试用期有年假吗"，**When** 我追问"那转正后呢？"，**Then** 系统理解指代，答案针对"转正员工的年假"作答，不重复上一轮内容。
- 关联：FR-QA-05

### US-08 无答案时诚实兜底

- **作为** 员工，**我希望** 系统答不上来时明确说"没找到"，**以便** 我不会被错误信息误导。
- **Given** 知识库中无任何食堂相关内容，**When** 我提问"公司食堂几点开饭？"，**Then** 系统回答未找到依据，并建议联系行政部门/补充文档，**不得** 编造时间。
- 关联：FR-QA-04

### US-09 问法宽泛时主动澄清

- **作为** 员工，**我希望** 得到引导而不是错误答案，**以便** 我换个问法再问。
- **Given** 我提问"住宿标准是多少"（未说明城市或场景），**When** 系统检索到多条不同标准，**Then** 答案列出适用条件或提示我补充信息（如"请说明出差城市级别"）。
- 关联：FR-QA-04、FR-QA-06

### US-10 知识库版本更新

- **作为** 管理员，**我希望** 上传新版制度并让旧版失效，**以便** 答案不引用过期制度。
- **Given** 旧版《报销制度》已入库，**When** 我上传新版并删除旧版，**Then** 重新提问时引用指向新版文件。
- 关联：FR-KB-05、FR-DOC-05

### US-11 查看知识库现状

- **作为** 管理员，**我希望** 看到已入库文档清单，**以便** 判断知识覆盖是否完整。
- **Given** 已上传 5 份文档，**When** 我打开知识库管理页，**Then** 表格展示 5 条记录（文件名/格式/切片数/时间/状态），数据与实际一致。
- 关联：FR-KB-04

### US-12 反馈答案质量

- **作为** 员工/管理员，**我希望** 对答案点赞或点踩，**以便** 团队能持续改进。
- **Given** 我已获得一条答案，**When** 我点击"👎"并填写原因，**Then** 反馈被记录，页面提示"感谢反馈"，主流程不受影响。
- 关联：UC-08

### US-13 回看历史会话

- **作为** 员工，**我希望** 找到昨天问过的问题，**以便** 不用重复提问。
- **Given** 我昨天有一次会话，**When** 我刷新页面并打开侧栏，**Then** 历史会话仍在，点击可恢复上下文。
- 关联：FR-CONV-01/02

### US-14 演示者稳定演示

- **作为** 演示者（U4），**我希望** 答辩现场不因网络或模型波动翻车，**以便** 完整展示系统价值。
- **Given** 现场网络不可用，**When** 我切换到演示模式并选择预置问题，**Then** 系统展示预先保存的带引用答案，流程不中断。
- 关联：FR-UI-05、FR-SEC-04

### US-15 开发者调用问答接口

- **作为** 开发者，**我希望** 接口返回结构化 JSON，**以便** 前后端解耦开发。
- **Given** 服务已启动，**When** 我 `POST /api/ask` 传入 `{"question": "年假有多少天"}`，**Then** 返回 `{"code":0,"message":"success","data":{"answer":..., "citations":[...]}}`，字段与 `docs/接口文档.md` 完全一致。
- 关联：FR-OPS-01、UC-10

### US-16 质量工程师量化评测

- **作为** Prompt 工程师（PE），**我希望** 有明确的评测口径，**以便** 两轮评测结果可比。
- **Given** 20 条评测集与知识库就绪，**When** 我执行评测脚本，**Then** 输出 M-01~M-04 四项指标数值与逐条明细，指标定义与本文档第 1.4 节一致。
- 关联：M-01~M-04、UC-12

- **P1 严重**：核心功能错误（答案无引用、引用指向错误文件）→ 3 天内修复；
- **P2 一般**：体验问题（文案、样式）→ 视排期修复；
- **P3 建议**：优化项 → 记入 v2 备选池。

## 13. 术语表

| 术语 | 含义 |
| :--- | :--- |
| RAG | 检索增强生成（Retrieval-Augmented Generation）：先检索企业文档，再让大模型基于检索结果作答 |
| 切片 / Chunk | 把长文档切成语义完整的小段，作为检索与引用的最小单位 |
| Embedding | 把文本转成向量，用于语义相似度检索 |
| 向量库 | 存储并检索向量的数据库，本项目使用 Chroma |
| Rerank | 重排序：对初步召回的候选片段做更精细的相关性排序，提升 Top-K 质量 |
| Top-K | 检索返回的候选片段数量 |
| 引用 / Citation | 答案所依据的原文出处（文件名 + 位置 + 片段） |
| 兜底 / 拒答 | 知识库中无依据时，明确告知未找到，而非编造答案 |
| Trace ID | 一次问答全链路的唯一标识，用于日志追踪与排障 |
| MoSCoW | 需求优先级方法：Must / Should / Could / Won't |
| GWT | Given-When-Then，验收标准的书写结构 |
| Recall@5 | 正确来源文档出现在检索前 5 条结果中的比例 |
| P95 | 95% 的请求耗时低于该值，衡量长尾时延 |
