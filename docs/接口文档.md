## 1. 通用约定

### 1.1 服务地址与环境

| 项 | 值 | 说明 |
| :--- | :--- | :--- |
| Base URL | `http://127.0.0.1:8000` | 本地开发/演示地址；前端通过环境变量 `WEB_API_BASE` 引用 |
| 接口前缀 | `/api` | 所有业务接口统一前缀 |
| 在线文档 | `GET /docs`（Swagger UI）、`GET /openapi.json` | FastAPI 自动生成，tag 按模块分组：health / chat / ask / documents / conversation |
| 数据格式 | 请求/响应均为 `application/json; charset=utf-8`；上传为 `multipart/form-data`；流式为 `text/event-stream` | — |

### 1.2 统一响应格式（FR-OPS-01）

**成功：**

```json
{
  "code": 0,
  "message": "success",
  "data": { }
}
```

**业务失败：**

```json
{
  "code": 2001,
  "message": "知识库为空，请先上传文档",
  "data": null
}
```

**参数校验失败（`data.errors` 逐字段说明，便于前端直接展示）：**

```json
{
  "code": 1001,
  "message": "参数校验失败",
  "data": {
    "errors": [
      { "field": "question", "reason": "问题不能为空" }
    ]
  }
}
```

**分页（所有列表接口统一）：**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "total": 10,
    "page": 1,
    "page_size": 20,
    "items": [ ]
  }
}
```

### 1.3 HTTP 状态码与业务 code 的关系

- HTTP 状态码表达**传输/资源语义**；响应体 `code` 表达**业务语义**；两者同时返回。
- 约定：**成功一律 HTTP 200 + `code=0`**；失败按下表映射；任何情况下响应体都是统一结构（不裸抛 500 页面）。
- 全局异常处理器（`app/core/errors.py`）负责兜底：未捕获异常 → HTTP 500 + `code=5000` + 中文提示，**不返回 Traceback**（NFR-R-04）。

### 1.4 错误码总表

| code | HTTP | 含义 | 面向用户的 message 示例 | 触发场景 |
| :--- | :--- | :--- | :--- | :--- |
| `0` | 200 | 成功 | `success` | — |
| `1001` | 400 | 参数校验失败 | 参数校验失败 | 字段缺失/类型错误（`data.errors` 明细） |
| `1002` | 415 | 文件类型不支持 | 不支持的文件类型：仅支持 PDF、Word(.docx)、Excel(.xlsx)、TXT、Markdown | 上传 `.exe/.doc/.zip` 等（FR-SEC-03） |
| `1003` | 413 | 文件超限 | 文件过大，单个文件请压缩到 20MB 以内 / 单次最多上传 5 个文件 | FR-DOC-02 |
| `1004` | 400 | 问题不合法 | 问题不能为空 / 问题过长，请精简到 500 字以内 | FR-QA-07 |
| `1005` | 404 | 资源不存在 | 文档不存在或已被删除 / 会话不存在 | FR-KB-05 |
| `1006` | 400 | 请求体格式错误 | 请求体不是合法的 JSON | body 解析失败 |
| `2001` | 409 | 知识库为空 | 知识库为空，请先上传文档 | 无任何成功入库的文档（FR-UI 空态） |
| `2002` | 422 | 文档解析失败 | 《xxx.pdf》解析失败：文件可能已损坏或为扫描件 | FR-DOC-04，逐文件结果中返回 |
| `2003` | 503 | 向量库异常 | 知识库暂时不可用，请稍后重试 | Chroma 读写异常 |
| `2004` | 409 | 文档重复 | 已存在同名文档，可选择覆盖或跳过 | 第3周 FR-DOC-05 |
| `3001` | 504 | 模型调用超时 | 回答生成超时，请稍后重试 | LLM 超时（重试 1 次后仍失败，NFR-R-02） |
| `3002` | 429 | 模型限流/额度不足 | 模型服务繁忙，请稍后重试 | 429/402 等上游限制 |
| `3003` | 500 | 未配置模型密钥 | 服务未配置模型密钥，请联系管理员 | `.env` 缺 `DEEPSEEK_API_KEY` |
| `3004` | 502 | 模型返回异常 | 回答生成异常，请重试 | 空响应/无法解析 |
| `5000` | 500 | 服务器内部错误 | 系统开小差了，请稍后重试 | 未捕获异常兜底 |

> 错误码分段（便于扩展）：`1xxx` 请求与校验 · `2xxx` 知识库/文档 · `3xxx` 模型与外部服务 · `5xxx` 服务端内部。

### 1.5 字段与命名规范

| 项 | 规范 | 示例 |
| :--- | :--- | :--- |
| 字段命名 | 一律 `snake_case`（不用驼峰） | `session_id`、`chunk_count` |
| 时间 | ISO 8601 带时区（+08:00） | `2026-10-01T10:20:30+08:00` |
| ID 规则 | `doc_{yyyymmdd}_{6位}`、`conv_{yyyymmdd}_{6位}`、`msg_{yyyymmdd}_{6位}`、`tr_{yyyymmdd}_{6位}`、`chunk_id = {doc_id}:{chunk_index}` | `doc_20261001_3f9a1c` |
| 枚举取值 | 小写英文，全表如下 | `status: processing/success/failed/deleted`；`answer_type: answered/not_found/clarify`；`file_type: pdf/docx/xlsx/txt/md`；`rating: up/down` |
| 数值 | 相似度 `score` ∈ [0,1]，保留 4 位小数；`latency_ms` 为整数毫秒 | `"score": 0.7231` |
| 空值 | 一律返回 `null` 而非空字符串（字符串字段） | `"sheet_name": null` |

### 1.6 安全约定（NFR-S-01~04、FR-SEC-02）

1. 接口响应**不返回** API Key、服务器绝对路径、Traceback；日志中 Key 脱敏为 `sk-****`；
2. v1 为单机单租户，**不做鉴权**；演示环境口令（FR-SEC-05）为第4周可选项，不影响本契约；
3. 上传文件名由服务端 sanitize 并重命名，接口返回的 `filename` 为原始文件名（已过滤控制字符）。

## 2. 接口详情

> 每个接口的结构：功能 → 请求（字段表 + 示例）→ 响应（字段表 + 示例）→ 错误码 → 实现提示。
> 字段表中的"必填"：**是** = 请求必须携带；**否** = 可省略，省略时用默认值。

### 2.1 API-01 健康检查 `GET /api/health`

**功能**：返回服务与依赖（LLM / Embedding / 向量库 / SQLite）状态，供演示前自检与运维排障（NFR-O-02）。

**请求**：无参数。

**响应字段**

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `status` | string | 总体状态：`ok` / `degraded`（有依赖异常） |
| `version` | string | 服务版本号 |
| `time` | string | 服务器时间（ISO8601） |
| `dependencies.llm.status` | string | `ok` / `error` / `unconfigured` |
| `dependencies.embedding.status` | string | 同上（含模型名与维度） |
| `dependencies.vector_store.status` | string | 同上（含集合名与切片总数） |
| `dependencies.sqlite.status` | string | 同上 |

**响应示例**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "status": "ok",
    "version": "0.1.0",
    "time": "2026-10-01T10:20:30+08:00",
    "dependencies": {
      "llm": { "status": "ok", "model": "deepseek-chat" },
      "embedding": { "status": "ok", "model": "BAAI/bge-small-zh-v1.5", "dim": 512 },
      "vector_store": { "status": "ok", "collection": "enterprise_kb", "chunk_count": 128 },
      "sqlite": { "status": "ok", "path": "data/app.db" }
    }
  }
}
```

**实现提示**：LLM 状态用一次轻量探活（或最近一次调用结果缓存，避免每次健康检查都花钱）；向量库用 `count()`；本接口**不抛异常**，依赖异常时也返回 200 + `status=degraded`。

### 2.2 API-02 基础对话 `POST /api/chat` 【第1周交付，W1-14】

**功能**：直连 DeepSeek 的多轮对话接口，**不检索知识库**。用于第1周打通模型链路、验证 Key 与网络；也是 `/api/ask` 的前置（复用同一 LLM 客户端）。

**请求字段**

| 字段 | 类型 | 必填 | 默认 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| `message` | string | 是 | — | 用户输入，1~2000 字 |
| `session_id` | string\|null | 否 | null | 传入则带上该会话历史（最近 10 轮）；不传则自动新建会话 |
| `system_prompt` | string\|null | 否 | null | 覆盖默认系统提示词（调试用，前端不暴露给普通用户） |
| `temperature` | float | 否 | 0.7 | 0~2 |
| `max_tokens` | int | 否 | 1024 | 1~4096 |
| `stream` | bool | 否 | false | true 时走 SSE（见 2.11，先实现非流式即可） |

**请求示例**

```json
{
  "message": "你好，请用一句话介绍企业知识库问答系统",
  "session_id": null,
  "temperature": 0.7,
  "stream": false
}
```

**响应字段**

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `trace_id` | string | 本次调用链路 ID（日志可查，FR-OPS-04） |
| `session_id` | string | 会话 ID（后续带此 ID 继续多轮） |
| `reply` | string | 模型回复文本 |
| `model` | string | 实际使用的模型名 |
| `usage.prompt_tokens / completion_tokens / total_tokens` | int | Token 用量（便于算成本） |
| `latency_ms` | int | 端到端耗时 |
| `created_at` | string | 生成时间 |

**响应示例**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "trace_id": "tr_20261001_b7c2e1",
    "session_id": "conv_20261001_7d2e10",
    "reply": "企业知识库问答系统让员工用一句话提问，即可从公司制度文档中得到带出处的答案。",
    "model": "deepseek-chat",
    "usage": { "prompt_tokens": 32, "completion_tokens": 58, "total_tokens": 90 },
    "latency_ms": 2310,
    "created_at": "2026-10-01T15:20:11+08:00"
  }
}
```

**错误码**：`1001`（message 为空/超长）、`3001`（超时）、`3002`（限流）、`3003`（未配置 Key）、`5000`。

**实现提示**
- `app/services/llm.py` 定义 `BaseLLM.chat(messages, **kwargs) -> LLMResult`，`DeepSeekClient` 基于 `openai` SDK（`base_url=https://api.deepseek.com`）实现；
- 超时 `LLM_TIMEOUT_SECONDS=60`、重试 1 次（`tenacity` 或手写循环）→ 仍失败抛 `BizError(3001)`；
- 消息落库到 `messages` 表（`session_id` 不存在时自动创建会话），供第3周会话历史复用。

### 2.3 API-03 上传并建库 `POST /api/upload` 【第2周交付】

**功能**：上传 1~5 个文档，解析 → 切片 → 向量化 → 入 Chroma，返回逐文件结果（UC-01）。

**请求**：`multipart/form-data`

| 字段 | 类型 | 必填 | 默认 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| `files` | file[] | 是 | — | 1~5 个文件；白名单 `pdf/docx/xlsx/txt/md`；单个 ≤ 20MB |
| `overwrite` | bool | 否 | false | 同名文件是否覆盖重建（第3周启用，FR-DOC-05） |

**请求示例（curl）**

```bash
curl -X POST http://127.0.0.1:8000/api/upload ^
  -F "files=@tests/sample_docs/01_员工手册.pdf" ^
  -F "files=@tests/sample_docs/03_报销制度与费用标准.xlsx" ^
  -F "overwrite=false"
```

**响应字段（`data`）**

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `total / succeeded / failed` | int | 本次上传统计 |
| `items[].doc_id` | string\|null | 成功时返回；失败为 null |
| `items[].filename` | string | 原始文件名 |
| `items[].file_type` | string | `pdf/docx/xlsx/txt/md` |
| `items[].size_bytes` | int | 文件字节数 |
| `items[].status` | string | `success` / `failed` / `skipped`（重复且未覆盖） |
| `items[].chunk_count` | int | 切片数（失败为 0） |
| `items[].elapsed_ms` | int | 该文件处理耗时 |
| `items[].error_code` | int\|null | 失败时的业务码（如 2002） |
| `items[].error_message` | string\|null | 中文失败原因 |

**响应示例（部分成功）**

```json
{
  "code": 0,
  "message": "上传完成：成功 1 个，失败 1 个",
  "data": {
    "total": 2,
    "succeeded": 1,
    "failed": 1,
    "items": [
      {
        "doc_id": "doc_20261005_3f9a1c",
        "filename": "01_员工手册.pdf",
        "file_type": "pdf",
        "size_bytes": 196254,
        "status": "success",
        "chunk_count": 42,
        "elapsed_ms": 3210,
        "error_code": null,
        "error_message": null
      },
      {
        "doc_id": null,
        "filename": "broken.pdf",
        "file_type": "pdf",
        "size_bytes": 10240,
        "status": "failed",
        "chunk_count": 0,
        "elapsed_ms": 150,
        "error_code": 2002,
        "error_message": "《broken.pdf》解析失败：文件可能已损坏或为扫描件"
      }
    ]
  }
}
```

**请求级错误 vs 逐文件结果（重要约定）**

| 情况 | 返回方式 |
| :--- | :--- |
| 未携带文件、超过 5 个文件、任一文件 > 20MB | **请求级失败**：`code=1003`（HTTP 413），整体拒绝 |
| 文件类型不在白名单 | **请求级失败**：`code=1002`（HTTP 415） |
| 解析失败 / 空文档 / 加密 PDF | **逐文件结果**：该条 `status=failed` + `error_code=2002` |
| 全部文件都解析失败 | 整体响应 `code=2002`（HTTP 422），`data.items` 仍逐条列出 |
| 部分成功 | `code=0`，`message` 提示"成功 X 个，失败 Y 个" |

**实现提示**：每个文件独立 try/except（NFR-R-01）；先写 `documents` 台账 `status=processing`，成功后更新 `chunk_count` 与 `status=success`；耗时超 60s 的大文件给出进度日志（NFR-P-03）。

| `chunk_count` | int | 切片数 |
| `upload_time` | string | 入库时间 |
| `status` | string | `processing/success/failed/deleted` |

**响应示例**

```json
{
  "code": 0,
```

### 2.6 API-06 RAG 问答 `POST /api/ask` 【第2周交付，核心接口】

**功能**：基于知识库回答问题，返回**答案 + 引用 + 检索明细**（UC-03/UC-04/UC-10，FR-QA-01~07、FR-CIT-01~04）。

**实现提示**
1. `answer_type` 判定顺序：检索有效候选为空 → `not_found`；候选互相冲突且问题缺少限定 → `clarify`（第3周实现，第2周可先返回 `answered`）；否则 `answered`；
2. `citations` 必须由程序根据 `[n]` 与 chunk 元数据生成（ADR-06），不得由模型直接输出文件名；
3. 生成后校验答案中的 `[n]` 是否越界，越界编号剔除并记 WARN 日志；
4. `not_found` 分支**不调用 LLM**（时延与成本双省），但 `retrieved` 仍需返回（PE 统计需要）；
5. 落库 `messages`：用户问题 + 助手答案 + `citations`(JSON) + `trace_id` + `latency_ms`。

### 2.11 API-07 流式问答（可选）`POST /api/ask` + `stream=true`

**响应头**：`Content-Type: text/event-stream; charset=utf-8`；**不走**统一响应包裹（流式协议本身即契约），事件序列如下：

```text
data: {"type":"retrieval","trace_id":"tr_20261008_9f3c2a","session_id":"conv_...","message_id":"msg_...","retrieved":[...],"citations":[...]}

data: {"type":"delta","content":"根据《员工手册》，"}

data: {"type":"delta","content":"入职满 1 年不满 10 年……"}

data: {"type":"done","usage":{"prompt_tokens":1532,"completion_tokens":128,"total_tokens":1660},"latency_ms":{"total":5200,"retrieval":320,"rerank":180,"generation":4700}}

data: {"type":"error","code":3001,"message":"回答生成超时，请稍后重试"}
```

**约定**：先发 `retrieval` 事件（前端可先渲染引用卡片），再发 `delta`；`done` 或 `error` 必为最后一个事件。第2周先实现非流式，本接口第3周按需启用。

## 4. 前后端联调约定（UI ↔ DEV）

### 4.1 前端调用示例（Streamlit 侧参考实现）

```python
# web/api_client.py  （UI 可参考此写法，统一封装、统一异常处理）
import os
import requests

BASE = os.getenv("WEB_API_BASE", "http://127.0.0.1:8000")
TIMEOUT = 120  # 生成类接口较慢，超时给足


def _post(path: str, payload: dict) -> dict:
    try:
        resp = requests.post(f"{BASE}{path}", json=payload, timeout=TIMEOUT)
    except requests.ConnectionError:
        return {"code": 5000, "message": "无法连接后端服务，请确认服务已启动", "data": None}
    except requests.Timeout:
        return {"code": 3001, "message": "请求超时，请稍后重试", "data": None}
    data = resp.json()
    if data.get("code") != 0:
        return {"code": data.get("code"), "message": data.get("message"), "data": None}
    return data


def ask(question: str, session_id: str | None = None) -> dict:
    return _post("/api/ask", {"question": question, "session_id": session_id})


def upload(files) -> dict:
    # multipart 用法：files=[("files", (name, bytes, mime)), ...]
    resp = requests.post(f"{BASE}/api/upload", files=files, timeout=600)
    return resp.json()
```
