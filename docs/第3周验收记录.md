## 二、逐项复核明细

### D2-01 表格型切片召回（P1，AD+DEV，看板 W3-02 标 ✅）

**修复动作**：`86c747d` Markdown 表格语义化渲染——两列表格渲染为「键：值」，丢弃管道符与分隔行。

**复核方法**：重建知识库后跑 20 条评测集（检索模式）+ 用缺陷清单记录的原问法直接复现。

| 验证项 | 结果 | 判定 |
| :--- | :--- | :--- |
| 切片文本已语义化 | `总部地址：浙江省杭州市滨江区星光大道 88 号星海大厦`（无管道符） | ✅ |
| 评测集问法「公司是什么时候成立的？总部在哪里？」 | 相似度 **0.5014** ≥ 阈值 0.485 → 命中，引用位置覆盖"一、公司概况" | ✅ |
| **缺陷原问法「公司总部在哪？」** | 相似度 **0.4608** < 阈值 0.485 → **无命中 → not_found 兜底** | ❌ |
| M-01 / M-04 是否劣化 | M-01 轮级 16/16 = 100%；M-04 = 5/5 = 100% | ✅ |

**判定**：**部分闭环**。评测口径已达标，但缺陷清单里记录的那个复现问法仍答不出——同一事实、不同问法，结果相反，说明问题本质不是"表格切片坏"，而是"短问法语义不足 + 单一阈值卡点"。

**建议**：不要用下调全局阈值（0.485）来处理——差 0.024，下调会同时放大越界问题的误召回（直接冲击 M-04）。优先复用第 3 周已建成的**查询改写**能力做单轮短查询扩展（如"公司总部在哪？"→"星海智联科技有限公司的总部地址在哪里？"），代价小、收益可量化；并把该问法补进回归用例。

### D2-02 引用编号连续性（P2）

**复核方法**：`POST /api/ask` 实测复合问题"年假和出差标准各是多少？"。

**结果**：答案引用为 `[1]`（员工手册 第 3 页）、`[2]`、`[3]`，编号连续且与 citations 数组一一对应，无跳号。**判定：✅ 闭环**（回归用例 `test_api_ask_offline.py::test_ask_citations_only_referenced` 已覆盖）。

### D2-03 端到端上传验证（P2）

**复核方法**：走真实 HTTP 接口做完整链路（本机浏览器自动化故障，故接口侧代为验证）。

| 步骤 | 实测结果 |
| :--- | :--- |
| 上传样例文档（md，ASCII 文件名） | `code=0`，入库 2 切片，`status=success` |
| 文档列表 | 由 10 条变 11 条，可见新文件 |
| 该文件参与问答 | 引用中出现该文件名，可在答案中被检索到 |
| 删除文档（W3-06） | `code=0`，`deleted_chunks=2`；列表回到 10 条、向量库回到 31 切片、`data/uploads/` 对应目录已清除 |
| 重复删除 | 返回业务码 `1005 文档不存在或已被删除`（与接口文档 1.4 一致，无副作用，幂等成立） |

**判定**：**接口侧端到端通过**。网页点击上传（含页面反馈、列表刷新）仍属未验证项，与看板 W3-16 的人工验证安排一致，建议 10-15 周会前由非开发成员完成并截图归档。

### D2-04 多轮历史注入定版（P3）

**复核方法**：核对 `537d6c6`（W3-08）与 `docs/多轮评测与A-B数据.md`。

**结果**：定版结论明确——维持「改写 + 文本注入」，不切换 messages 注入；依据为四方案 A/B（文本注入重复率 7.5%~12.8% vs messages 18.5%，>30% 轮次 1/7 vs 2/7，messages 方案另有 1 例要点缺失）；已写入架构 8.2 + ADR-09。**判定：✅ 闭环**。

**保留意见（非阻塞）**：该结论基于 8 用例 × 单次采样，PE 已在文档中自述噪声局限。建议第 3 周《质量报告》按承诺多次采样复核，尤其关注 MT-03（重复率最高的用例）。

### D2-05 引用位置粒度（P3，AD，看板 W3-03 ⬜）

**复核方法**：实测 FAQ 类问题"FAQ 里怎么申请 VPN 权限？"，查看引用位置文本。

**结果**：引用位置为
`章节「员工常见问题 FAQ（2026 版）」~「员工常见问题 FAQ（2026 版） > 4. 如何申请 VPN 权限？」`
——跨度覆盖 FAQ 第 1~4 条，用户按此位置仍需自行翻找。**判定：❌ 未修复**（W3-03 状态为 ⬜ 未开工，计划截止 10-17）。
