## 1. 设计原则

1. **事实唯一**：每题的标准答案只对应示例数据包中的一处事实，便于判定 M-01（来源命中）与 M-02（引用准确）。
2. **分布对齐需求**：难度 8 易 / 9 中 / 3 难；覆盖制度查询、流程查询、表格取数、多轮追问、无答案兜底五类题型。
3. **拒答题不少于 4 条**：实际设置 5 条（与 M-04「5 条诱导问题」的测量口径一致），示例数据刻意不含食堂、停车位、班车、年会、营收信息。
4. **含干扰项**：QA-014（陪产假）用于检验是否误引《员工手册》；QA-020（营收）用于检验是否误用《供应商对账明细》的金额表。
5. **可自动判分**：每题给出 `key_points`（要点清单）与 `answer_type`，供评测脚本与人工复核共用。

## 2. 字段说明

| 字段 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| `id` | string | 是 | 题号，形如 `QA-001`，全表唯一 |
| `question` | string | 是 | 用户提问原文（口语化，符合真实提问习惯） |
| `expected_answer` | string | 是 | 参考答案（要点式，含全部关键事实） |
| `expected_source` | string\|null | 是 | 期望来源文件名；拒答题为 `null` |
| `expected_location` | string\|null | 是 | 期望引用位置（页码 / 工作表 / 章节）；拒答题为 `null` |
| `type` | string | 是 | 题型：制度查询 / 流程查询 / 表格取数 / 多轮追问 / 无答案兜底 |
| `difficulty` | string | 是 | 难度：`easy` / `medium` / `hard` |
| `tags` | string[] | 是 | 关联编号：`D-xx`（示例文档编号）与需求编号（`FR-*` / `M-*`） |
| `answer_type` | string | 是 | 期望的接口返回类型：`answered` / `not_found`（对齐接口文档 1.5） |
| `key_points` | string[] | 是 | 关键要点清单，用于 M-03 的「完整=1 / 部分=0.5 / 错误=0」评分 |
| `follow_up_questions` | string[] | 否 | 多轮追问题专用：同一会话中的后续提问 |
| `notes` | string | 否 | 判分注意事项、干扰项说明、易错点提示 |

> 前 8 个字段与 `docs/需求文档_v1.md` 7.3 一致；`answer_type` / `key_points` / `follow_up_questions` / `notes` 为 PE 扩展字段，仅用于评测与复核，不影响接口契约。

## 4. 指标口径（与需求文档 1.4 一致）

| 指标 | 统计对象 | 判定规则 |
| :--- | :--- | :--- |
| M-01 检索命中率 Recall@5 | 15 条可答题 | 该题的正确来源文件出现在 `retrieved` 前 5 条中即命中；多轮题 QA-015 要求两轮均命中；目标 ≥ 80% |
| M-02 引用准确率 | 15 条可答题 + 5 条拒答题 | 人工核对 `citations[].snippet` 是否支撑答案结论、`source_file` / `location` 是否与 `expected_source` / `expected_location` 一致；拒答题应 `citations=[]`；目标 ≥ 85% |
| M-03 答案正确率 | 15 条可答题 | 对照 `key_points` 打分：完整 = 1、部分 = 0.5、错误或缺失 = 0；总分 ÷ 15；目标 ≥ 75% |
| M-04 拒答正确率 | 5 条拒答题 | `answer_type = not_found`、`citations = []`、答案无编造事实，三条同时满足才算正确；目标 ≥ 90%（5 条全对 = 100%） |
| 时延（辅助） | 20 次调用 | 记录 `latency_ms.total` 与 `retrieval`，用于 M-05 的 P95 统计（DEV 主责，PE 顺带记录） |

判定细则：

1. 答案给对但来源引到错误文件 → 计入 M-01 未命中、M-02 不通过（沿用 `docs/示例数据说明.md` 第 3 节的口径）。
2. QA-011（住宿标准）允许两种表现：直接列出三档，或先追问城市级别再给对应档位；只要关键数值正确即计 M-03 满分。
3. QA-006 的「提前 3 个工作日」仅在 FAQ 中出现，引用《报销制度与费用标准》属于引用不充分。
4. 多轮题 QA-015 第 2 轮若重复输出第 1 轮内容，最多计 0.5 分。

## 5. 评测执行流程（第 2 周首跑，第 3 周复跑）

1. 重建知识库：用 `scripts/init_kb.py` 导入 `tests/sample_docs/` 全部 10 份示例文档（D-01~D-10），确认切片数均 > 0；
2. 逐条提问：默认参数 `top_k=5`、`score_threshold=0.35`；每条题目使用**独立会话**，多轮题 QA-015 在同一 `session_id` 内连续两问；
3. 记录原始结果：`answer`、`answer_type`、`citations`、`retrieved`、`latency_ms`，按 `trace_id` 归档；
4. 计算指标：脚本 `scripts/eval_rag.py`（PE 第 2 周实现）输出 M-01~M-04 数值与逐条明细；
5. 结果归档：写入 `docs/质量报告.md`（第 3 周交付），并保留可复现的原始 JSON 记录。

## 7. 维护规则与已知限制

1. 修改题目必须同时更新：本文件第 3、6 节 → `docs/需求文档_v1.md` 7.3 的分布说明 → 文件版本号（如 `qa_dataset_v2.json`），三处保持一致。
2. 示例文档内容变更后，先运行 `py -3 scripts/check_qa_dataset.py`，确认 `expected_source` 指向的文件仍存在、分布仍达标。
3. 已知限制：（a）v1 未设置 `clarify` 类题目，第 3 周阈值调优时增补；（b）D-02 未直接出题，第 2 周可增补 1~2 题（如版本功能对比表取数）；（c）每题仅给出单一 `expected_source`，多来源题（如 QA-006）在 `notes` 中单独说明。
