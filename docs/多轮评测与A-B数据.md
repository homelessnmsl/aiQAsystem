## 2. 评测口径

| 指标 | 口径 |
| :--- | :--- |
| M-01 检索命中（轮级） | 应可答轮：正确来源出现在该轮 `retrieved` 前 5 条的比例 |
| 答案要点（自动预评） | 对照逐轮 `key_points`：关键数字命中率 100% 记 1.0、≥60% 记 0.5；无数字要点按中文双字覆盖率 ≥70% 判定。整题取两轮最低分；**以人工复核为准** |
| 重复率（多轮） | 本轮答案与上一轮答案的 8 字片段重合占比；> 30% 记为“明显重复”（拒答轮不参与统计） |
| M-04 拒答 | 拒答轮：`answer_type=not_found`、无引用、答案无数字 |
| 时延 | 逐轮端到端时延（检索 + 改写 + 生成） |

## 4. 主要发现

1. **追问改写有效且无副作用**：8 条追问全部被改写为自包含问题（如“那转正之后呢？”→“员工转正之后的年假如何计算？”；“那附近有什么好吃的推荐吗？”→“公司食堂附近有什么好吃的推荐？”），四个方案 M-01 均为 14/14，说明改写后检索仍能命中正确文档，追问不再“断链”。
2. **文本注入优于 messages 注入（现方案胜出）**：重复率均值 7.5%~12.8% vs 18.5%，>30% 的轮次 1/7 vs 2/7；且 messages 方案出现 1 例要点缺失（MT-08 病假答案漏“每年累计不超过 30 天”）。**没有证据支持切换到 messages 注入。**
3. **超长答案是真实风险**：生产链路（temperature=0.3）MT-03 轮 1 输出 281 字、基线 213 字，均超出“≤200 字”约束；离线路径（0.2）为 129 字。已据此发布 **Prompt v1.2**（超 200 字时只保留与问题直接相关的要点），复测见附录 B。
4. **拒答在多轮下依旧稳定**：MT-06 第 2 轮改写为“公司食堂附近有什么好吃的推荐？”后仍未越过阈值，直接兜底（时延 18ms，不调用大模型），与单轮集 M-04 = 100% 的结论一致。
5. **局限**：8 用例 × 单次采样，方案间差异可能含模型噪声；本数据作为 W3-08 选型输入，正式结论在第 3 周质量报告中以更多用例复核。

## 5. 选型建议（提交 W3-08 / D2-04 定版参考）

1. **维持现行「改写 + 文本注入」**（即 A/B 同构、生产路径 B），不切换 messages 注入；
2. 若第 4 周确需压缩上下文，优先评估“改写 + 最近 1 轮摘要”，而不是全量 messages 注入（后者在本次数据中重复率更高、且有要点缺失）；
3. **Prompt v1.2 随本分支合并后生效**，建议 DEV 在 W3-08 定版时同步确认文案；
4. 第 3 周随 Rerank 启用后，用本用例集复跑一次，观察改写 + 重排的组合效果。

## 6. 定版结论（W3-08 / D2-04，DEV + PE，2026-10-09）

**决定**：维持「**改写 + 文本注入**」为多轮对话正式方案（不切换 messages 注入）。

- **依据**：四方案 A/B（第 3 节）——文本注入重复率 7.5%~12.8% vs messages 18.5%，
  >30% 轮次 1/7 vs 2/7，且 messages 方案出现 1 例要点缺失（MT-08）；M-01 均 14/14；
- **落地**：已在 `/api/ask` 生产链路生效（检索前改写 `_rewrite_question`；最近 3 轮
  「用户：/助手：」文本注入 `${history}`）；改写失败自动降级原文检索；
- **Prompt**：v1.2 已合并生效（超 200 字只保留直接相关要点；复测 0 轮超限）；
- **归档**：已写入 `docs/架构设计.md` 8.2 + ADR-09；本文件作为 W3-08 定版结论存档；
- **后续**：第 4 周如需压缩上下文，优先评估"改写 + 最近 1 轮摘要"，而非全量 messages 注入；
  第 3 周《质量报告》以更多用例复核本结论。
