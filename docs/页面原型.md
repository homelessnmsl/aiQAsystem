**交互要点**

1. 三个示例问题可**一键提问**（点击后等同于用户输入，降低上手门槛）；
2. 输入框始终固定在底部，滚动对话流时不遮挡；
3. 后端未连接时：不隐藏输入框，但提问后给出中文错误提示 + 「重试这次提问」。

### 2.2 正常问答（answered：答案 + 引用折叠条）

```text
┌─ 主区 ────────────────────────────────────────────────────────────────┐
│ 你                                                                     │
│   公司年假有多少天？                                                    │
│                                                                        │
│ 助手  〔已找到依据〕  ← 三态徽章（绿：answered / 橙：not_found / 蓝：clarify）│
│   按《员工手册》规定，年假天数按司龄分档：                                │
│   • 满 1 年不满 10 年：5 天/年 [1]      ← [n] 为可点击序号锚点，蓝色上标   │
│   • 满 10 年不满 20 年：10 天/年 [1]                                    │
│   • 满 20 年以上：15 天/年 [1]                                          │
│   注意：试用期不享受年假，转正后按剩余日历天数折算 [1]                     │
│                                                                        │
│   📎 引用来源（1）— 点开可核对原文                                       │
│   ▸ [1] 📄 01_员工手册.pdf · 第 3 页 · 相关度 0.86        ← 折叠条（默认收起）│
│       ┌─ 展开后 ────────────────────────────────────────────┐            │
│       │ ▏第三章 假期管理：员工累计工作满 1 年不满 10 年的，    │            │
│       │ ▏年休假 5 天；满 10 年不满 20 年的，年休假 10 天……    │            │
│       │ doc_id: doc_xxx · chunk_id: doc_xxx_c003             │            │
│       └─────────────────────────────────────────────────────┘            │
│                                                                        │
│   ▸ 检索详情（Top-5，评测与排障用）                                       │
│   耗时 3.4s ｜ deepseek-chat ｜ trace_id tr_20260928_000123              │
│   [👍 有帮助] [👎 不准确]                                                │
└───────────────────────────────────────────────────────────────────────┘
```

| 元素 | 规格 | 依据 |
| :--- | :--- | :--- |
| 答案正文 | 中文、要点式、≤200 字、结论后带 `[n]` | 需求 8.3、架构 6.9 |
| 序号锚点 | 蓝色上标 `[1]`，与折叠条序号一一对应 | FR-UI-04、8.3 |
| 引用折叠条 | 标题＝`[序号] 📄 文件名 · 位置 · 相关度`；展开＝原文片段 + doc_id/chunk_id | FR-CIT-02/03、US-04 |
| 位置格式 | PDF/Word → `第 N 页`；Excel → `「工作表名」· 第 a~b 行`；TXT/MD → `第 a~b 行` | FR-CIT-02、ADR-07 |
| 表格类答案 | 保留原始行列结构（前端不拆行） | 需求 8.3 |

### 2.3 兜底与澄清（not_found / clarify）

```text
〔未找到依据〕
⚠ 未在知识库中找到相关依据，因此不作推测性回答。
  建议：换一种问法，或联系管理员补充相关文档后再试。

（引用区显示："本条回答没有引用来源（未在知识库中找到依据）"，不显示 👍/👎）

〔需要补充信息〕
ℹ 知识库中存在多档住宿标准，需要你补充一个信息：出差城市属于哪一级？
  • 一线 500 元/晚   • 二线 400 元/晚   • 其他 300 元/晚
  例如补充：出差城市级别、员工职级或具体场景。
```

对应 US-08（诚实兜底，不得编造）与 US-09（主动澄清），`answer_type` 取值见架构 6.10。

### 2.4 错误态与加载态

```text
加载态（提问后）：
  ⏳ 正在检索知识库…            ← 优先展示在助手气泡内，避免"点了没反应"

错误态（后端未启动 / 超时 / 未配置 Key）：
  ✖ 无法连接后端服务
    后端服务似乎没有启动（或网络不通）。请确认后端已在 127.0.0.1:8000 运行；
    演示现场可打开左侧「演示模式」，用预置问答继续演示。
    [重试这次提问]
  排障编号（trace_id）：tr_...
```

错误码 → 文案映射集中在 `web/api_client.py::ERROR_HINTS`，与架构 8.3 失败降级表一一对应；**任何情况下都不向业务用户暴露堆栈或绝对路径**。

## 5. 关键交互流程

```text
提问链路（第1周：演示模式可完整跑通；第2周接真实 /api/ask）
用户输入 → 加载态 → [demo?] ─是→ 预置答案(含引用)
                          └否→ POST /api/ask
                                ├ 成功 → 渲染答案 + 引用折叠条 + 检索详情 + 反馈
                                ├ not_found → 中性兜底 + 不给反馈按钮
                                └ ApiError → 中文错误块 + [重试这次提问]（不重复插入用户气泡）

上传链路（第2周接 /api/upload）
选择文件 → 客户端校验（扩展名/≤20MB/≤5个）→ 不通过：中文拦截
        → 通过：POST /api/upload（multipart）→ 逐文件结果（失败隔离）→ 刷新文档列表
```

## 7. 接口契约对齐（已按 `docs/接口文档.md` v1 逐条核对）

第1周 AD 已交付接口文档，前端 `web/api_client.py` 已据此实现（2026-09-28 复核，字段名 100% 对上）：

| 接口 | 前端使用的字段 | 对齐情况 |
| :--- | :--- | :--- |
| `POST /api/ask` | `answer`、`answer_type`(answered/not_found/clarify)、`citations[]{index,doc_id,source_file,location,snippet,score,rerank_score,chunk_id}`、`retrieved[]{…,rank}`、`session_id`、`message_id`、`trace_id`、`latency_ms`、`model` | ✅ 一致（与需求 7.4 数据字典一致） |
| `POST /api/chat` | 请求 `message`、`session_id`；响应 `reply`、`model`、`usage`、`latency_ms` | ✅ 一致（**第1周即可联调**，见接口文档 2.2） |
| `POST /api/upload` | `total`、`succeeded`、`failed`、`items[]{doc_id,filename,file_type,size_bytes,status,chunk_count,elapsed_ms,error_code,error_message}` | ✅ 一致（部分成功仍为 `code=0`，逐文件展示） |
| `GET /api/documents` | `total`、`page`、`page_size`、`items[]{doc_id,filename,file_type,size_bytes,chunk_count,upload_time,status}` | ✅ 一致 |
| `DELETE /api/documents/{doc_id}` | `doc_id`、`deleted_chunks` | ✅ 一致（第3周交付，界面已预留二次确认） |
| `POST /api/feedback` | 请求 `message_id`、`session_id`、`rating`(up/down)、`comment` | ✅ 一致（第3周交付） |
| `GET /api/health` | `status`、`version`、`dependencies.{llm,embedding,vector_store,sqlite}.status` | ✅ 一致（侧栏状态灯按 `status` + 四项依赖展示） |

补充说明：

1. `location` 由**后端拼好中文短句**（如 `第 3 页`、`工作表「差旅标准」第 12~31 行`），前端直接展示，不再二次拼接；
2. 错误码 → 中文文案映射见 `web/api_client.py::ERROR_HINTS`（覆盖 1001~1006、2001~2004、3001~3004、5000），与接口文档 1.4 / 4.2 完全一致；
3. `code=1001` 时若返回 `data.errors[]`，前端会逐条展示 `reason`（接口文档 4.2 要求）；
4. 为防接口联调期字段微调，`api_client.py` 仍保留同义字段兼容（如 `answer`/`reply`/`content`）与默认值，**字段缺失不会把页面打崩**。
